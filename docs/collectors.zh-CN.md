# 采集器契约

[English](collectors.md)

采集器负责将一个外部来源转换为忠实于来源的记录。采集器不能直接写入 SQLite，不能跨来源去重，不能推断来源没有说明的事实，也不能评估签证难度。

## 系统边界

统一流程为：

```text
Collector -> RequestSpec -> Transport -> RawSnapshot
          -> SourcePosting + ParseIssue -> CollectionBatch
          -> 规范化与数据库写入（独立组件）
```

`Transport` 是唯一允许的网络边界。测试使用内存实现替代它，因此采集器测试不会访问互联网。

## 必须遵守的行为

每个采集器必须：

- 提供稳定的 `source_id`；
- 只能通过 `Transport` 发出请求；
- 保留来源记录 ID、URL、原始日期文本、门槛和技能描述；
- 返回带有已验证 SHA-256 哈希的不可变快照；
- 区分来源明确表示没有岗位与解析器无法识别页面结构；
- 使用结构化问题记录，不能静默丢弃格式异常的岗位；
- 批次状态为 `failed` 时不能返回可写入数据库的记录；
- 对同一快照产生确定且可重复的结果。

## 批次状态

| 状态 | 含义 |
|---|---|
| `success` | 已正确理解来源，所有返回记录都有效。来源明确表示没有岗位时也可以成功。 |
| `partial` | 同时发现至少一条有效记录和至少一个记录级错误。 |
| `not_modified` | 传输层确认来源没有变化。 |
| `failed` | 无法信任响应或页面结构，不能写入任何岗位记录。 |

## 新增来源的步骤

1. 启用采集前登记并审查来源。
2. 在 `src/astrocareer/collectors/` 下添加采集器模块。
3. 在 `tests/fixtures/<source_id>/` 下添加经过最小化处理的本地测试页面。
4. 测试正常页面、明确空列表、异常记录和页面布局变化。
5. 验证来源记录 ID 与规范 URL 是否稳定。
6. 记录哪些字段无法可靠提取。
7. 在 robots、使用条款、访问频率及再发布限制完成记录前保持禁用。

## 解析规则

- 规范化之前必须保留官方原文。
- 不能把“优先考虑”转换成“必须具备”。
- 不能自行编造日期、时区、报名人数、签证担保或合同条件。
- 没有说明意味着 `not_reported`，不等于否定。
- 岗位暂时从列表消失不能证明岗位已经撤销。
- 除非来源明确表示列表为空，否则解析结果为零应当视为错误。

## 当前实现

`DemoCollector` 及其 `.test` 测试页面在不访问网络的情况下验证了上述契约。`PlanetaryResearchFeedCollector` 是第一个经过审查的真实来源适配器。它只读取官方 Atom feed，最多接受 1,000 条记录，验证 feed 与条目身份，拒绝 DTD/实体声明，并主动丢弃完整正文、联系人信息和发布者 ORCID 标识。

在项目具备公开联系 URL 前，该真实来源仍保持禁用。解析器已经通过合成夹具及一次临时真实 feed 快照验证；真实响应不会提交到仓库。
