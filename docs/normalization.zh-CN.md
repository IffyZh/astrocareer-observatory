# 规范化与审核

[English](normalization.md)

规范化层将忠实于来源的 `SourcePosting` 转换成可审核的 `NormalizedPostingCandidate`，不能直接修改正式岗位。

## 安全模型

- 每个规范化值都保留对应原文。
- 只有确定、可记录的规则才能产生规范化值。
- 来源没有相关文字时使用 `not_reported`。
- 来源有相关文字但规则不支持或内容冲突时使用 `ambiguous`。
- 将两年换算为24个月等可复现计算使用 `derived`。
- 候选记录以 `review_status = pending` 进入数据库。
- 将候选接受为正式岗位需要独立审核操作，目前尚未实现。

## 当前支持的规则

当前 MVP 规则可以识别：

- ISO日期、ISO日期时间，以及来源给出的“月份+年份”入职时间；
- 基于岗位标题和已审核来源分类的小型岗位类别词表；
- 明确说明的永久、固定期限、Fellowship和临时合同；
- 没有歧义、以月或年说明的合同期限；
- 来源明确给出的岗位数量，以及保守识别的续约可能性；
- 明确FTE数值和没有歧义的全职表述；
- 使用常见币种标记且明确计薪周期的薪资；只有同一条记录明确说明岗位位于美国时，单独的 `$` 才按美元处理；
- 税前或税后薪资表述；
- 现场、混合、远程和灵活工作表述；
- 来源明确提到的英语、葡萄牙语、西班牙语、法语和德语。

词表有意保持很小。不支持的表述会保留等待审核，而不是强行猜测。

对于 Planetary Research Jobs feed，MVP 还会保留来源分类、部门、参考编号、聚合站条目链接和官方公告链接。官方公告链接只作为数据保存，采集器不会请求或跟踪它。由于已审核的 feed 摘要没有提供求职门槛、技能、报名人数、录用人数和外国申请资格，这些字段继续保持 `not_reported`，不会从其他信息猜测。

## 审核状态

| 状态 | 含义 |
|---|---|
| `pending` | 等待审核，对正式岗位没有影响。 |
| `accepted` | 已由未来的审核流程批准。 |
| `rejected` | 已审核并明确拒绝。 |
| `superseded` | 已被更新候选或新版规则替代。 |

数据库保存规范化规则版本和候选SHA-256，因此重复运行相同规则不会产生重复记录，规则变化也可以审计。
