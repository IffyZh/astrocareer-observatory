# AstroCareer Observatory（天文学职业市场观测站）

[English](README.md)

> 一个用于长期观察天文学与天体物理就业市场、强调来源可追溯性的开放数据库。

AstroCareer Observatory 目前处于预开发阶段。项目将收集、规范化并保存天文学、天体物理、科研软件、科学计算和研究基础设施岗位的公开信息。

它首先是一项服务于个人职业研究的实用工具。项目会公开开发代码、方法以及允许再发布的数据，使其他人能够检查、使用和共同维护。

## 为什么建立这个项目

招聘网站适合寻找当前职位，却通常不会保留完整、可复现的历史记录。不同网站对合同类型、岗位类别、申请资格、技能和截止日期的描述也不一致。

本项目希望建立一套纵向数据，用于研究以下问题：

- 随时间变化，实际观察到多少相关岗位？
- 哪些国家和机构发布永久或长期岗位？
- 哪些研究与技术技能最常出现？
- 哪些职位接受国际申请者或提供签证支持？
- 在存在官方证据时，有多少人申请、进入面试或最终被录用？
- 各来源覆盖范围的变化会如何影响看起来的市场趋势？

## 项目原则

### 可追溯性优先于数量

重要事实应保留来源 URL、观察时间、内容哈希、解析器版本和核查状态。来源没有提供的信息必须保持缺失，不能在缺少证据时自行推断。

### 保存历史

数据库应区分公告发布时间、系统首次发现时间和最后观察时间。更新、撤销、截止等状态变化应追加为事件，而不是静默覆盖旧记录。

### 区分观察与解释

来源原文、规范化字段、人工分类和分析结论不是同一种数据。数据模型应保留这些层次之间的区别。

### 明确说明覆盖范围

观察到的招聘数量取决于系统监测了哪些来源，以及采集器当时是否正常工作。必须记录覆盖范围变化，避免将采集范围扩大误判为就业市场增长。

### 尽量减少个人数据

公开项目研究的是岗位与市场层面的证据，而不是申请者公开档案。项目不会自动聚合具名申请者的职业历史。个人申请记录、岗位排序、联系人和私人评价应保存在独立的私有层中。

### 负责任地采集数据

每个来源在启用自动采集前都必须经过审查。优先使用官方 API、订阅源或其他明确支持的访问方式，并遵守 robots 规则、使用条款、访问频率、版权和再发布限制。

## 计划公开的数据

在各来源许可范围内，公开数据可以包括：

- 岗位名称、类别、机构与地点；
- 发布、截止和系统观察时间；
- 来源明确说明的合同类型与期限；
- 可获得的薪酬、语言、申请资格和签证信息；
- 研究与技术技能要求；
- 来源链接和可追溯性元数据；
- 有记录支持的岗位状态变化；
- 有官方依据的汇总竞争统计。

来源中出现某项信息，并不自动代表项目有权重新发布其完整原文。代码许可证与第三方数据权利将分别处理。

## 第一版不包括的内容

- 自动建立具名申请者或成功候选人的公开档案；
- 根据 Rumor Mill 或不完整公开名单推断申请人数；
- 将个人求职概率评分包装成客观预测；
- 高频抓取或绕过访问限制；
- 宣称项目能够完整覆盖全球市场。

## 第一个里程碑

第一阶段计划实现：

1. 为来源、岗位、观察记录、证据和事件建立有文档的数据模型；
2. 建立本地 SQLite 数据库；
3. 提供能够导入测试样本并导出小型公开数据集的命令行流程；
4. 建立自动校验与测试；
5. 完成一个经过规则审查、便于维护的真实数据采集器。

## 当前状态

**Pre-alpha（预开发阶段）。** 项目已经为一个经过审查的 Atom feed 来源启用定时采集。内部 SQLite 状态以短期 GitHub Actions artifact 保存，目前尚未正式发布公开数据集；此外还实现了一个离线 ROR 机构目录导入器。

在第一个带版本号的发布之前，接口、数据库模式和仓库结构都可能改变。

采集器使用带版本的插件 API。可以运行 `PYTHONPATH=src python3 -m astrocareer plugins list` 查看可用适配器；如需在不修改采集运行器的情况下增加来源，请参阅[采集器插件开发指南](docs/plugin-development.zh-CN.md)。

## 本地数据库快速开始

在源码仓库中，可以使用以下命令初始化一个空的 schema-v8 SQLite 数据库：

```bash
PYTHONPATH=src python3 -m astrocareer db init data/local/astrocareer.sqlite3
```

该命令会按需创建父目录、启用外键检查、执行随包分发的数据库迁移，并运行 SQLite 完整性检查。Git 默认忽略本地 `*.sqlite3` 文件。

新初始化的数据库只有结构。经过审查的来源定义和数据集需要显式同步或导入。

可以使用以下命令载入明确标记为虚构的演示数据：

```bash
PYTHONPATH=src python3 -m astrocareer db seed-demo data/local/astrocareer.sqlite3
```

该命令可以安全地重复运行。演示机构、政策和 `.test` URL 均不真实，不能用于就业市场分析。

使用以下命令将经过审查的来源登记同步到数据库：

```bash
PYTHONPATH=src python3 -m astrocareer db sync-sources \
  data/local/astrocareer.sqlite3 data/sources.toml
```

网络采集来源在完成明确审查和启用前保持禁用。获批的离线导入可以启用，但这不会授予网络访问能力。

下载并解压官方 ROR Schema 2.x JSON 数据快照后，可以这样导入机构记录：

```bash
PYTHONPATH=src python3 -m astrocareer db import-ror \
  data/local/astrocareer.sqlite3 /path/to/ror-data.json \
  --dataset-version vX.Y-YYYY-MM-DD \
  --registry data/sources.toml
```

导入按文件哈希保持幂等，并记录数据集版本。导入 ROR 不会访问或抓取任何机构网站。

可以在完全不写入数据的情况下，用本地fixture运行虚构采集器：

```bash
PYTHONPATH=src python3 -m astrocareer collect-fixture \
  demo-html-source tests/fixtures/demo_source/normal.html \
  --database data/local/astrocareer.sqlite3 \
  --registry data/sources.toml \
  --dry-run
```

开发字段规则时，可以把经过审查的网络响应捕获一次并保存在被 Git 忽略的 `data/local/` 下，之后反复离线重放。详见双语[采集运行器说明](docs/runner.zh-CN.md)。

可以用以下命令在本地只读浏览器中查看最新的结构化候选：

```bash
PYTHONPATH=src python3 -m astrocareer db browse \
  data/local/astrocareer.sqlite3
```

该命令只监听 `127.0.0.1`，会自动打开系统浏览器，并持续占用终端，直到按下 `Ctrl+C`。使用 `--port 0` 可以自动选择空闲端口；在没有桌面浏览器的环境中可加 `--no-open`。
